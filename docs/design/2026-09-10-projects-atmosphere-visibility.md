# 2026-09-10 Projects 散点氛围层可见度调整设计

对应来源：用户聊天反馈（2026-09-10）「似乎你没有实现背景的散点图效果？」→ 诊断后确认已实现但几乎不可见，用户选择**调整可见度**。
关联前作：[`2026-09-09-projects-enhancement2`](../design/2026-09-09-projects-enhancement2.md) 的需求②散点氛围层。

> 本文档由聊天确认的需求驱动，**未新增正式需求文件**（属对既有已验收视觉的微调）。

## 1. 诊断结论（已实测验证）

散点效果**已正确实现并构建**，不是缺失，而是肉眼不可见。证据：

- 构建产物 `dist/projects/index.html` 中数出 **46 个** `<span class="project-atmosphere__dot">`，样式与动画齐备；
- `.project-atmosphere__dot { background: var(--text); border-radius: 50%; ... }` 与 `dot-float` 浮动动画均在打包 CSS 内；
- 根因是 **生成参数过于克制**，导致 1x 屏上接近背景色：

| 参数 | 现值 | 问题 |
|---|---|---|
| 直径 `size` | 1–3 px（多数 1.2–2.6px） | 太小，低于可辨识下限 |
| 不透明度 `opacity` | 0.05–0.13 | 太淡，把近黑/近白点压到近乎融于底色 |
| 数量 | 46 个 / 宽版内容区 | 分布偏稀（内容列最高可达 ~1680px 宽） |

配色本身是**正确的**：浅色主题 `--text:#282828`（近黑），深色主题 `--text:#e8e5df`（近白），散点颜色随 `--text` 自动适配两种主题，无需改色。

## 2. 目标

让散点从「几乎不可见」提升到「**隐约可感的氛围颗粒**」——仍必须是背景、不喧宾夺主、不与前景卡片抢注意力，但用户能明确感知这一层存在。

**不改变**：散点的静态渲染方式（无 JS/CANVAS）、固定种子 LCG、浮动动画手法、`prefers-reduced-motion` 降级、`.project-section` 承载结构、颜色来源 `var(--text)`。

## 3. 参数调整方案

### 3.1 新生成区间（改 `ProjectAtmosphere.astro` 内 LCG 范围）

| 参数 | 现值 | 建议值 | 理由 |
|---|---|---|---|
| 直径 `size` | 1–3 px | **2–4.5 px** | 下限提到 2px 保证可见，上限 4.5px 制造少量大小节奏，不越"颗粒"尺度 |
| 不透明度 `opacity` | 0.05–0.13 | **0.12–0.26** | 整体抬高一倍上下；上限 0.26 仍远低于文字，保证"氛围"而非"噪点" |
| 数量 | 46 | **60** | 略微加密，补偿宽版内容区的稀散 |

对应的 LCG 采样公式（保持整型定点随机，输出稳定）：
- `size`: `2 + rand() * 2.5` → 取 1 位小数，范围 2.0–4.5px
- `opacity`: `0.12 + rand() * 0.14` → 取 2 位小数，范围 0.12–0.26
- `count`: `dots(60)`
- 种子 `20260910`（可保留 `20260909`；如需散点位置全部变化以利 A/B 对比，建议换种子到当日）

### 3.2 明暗主题对比度验算

散点色随 `--text`，故两种主题对比方向相反，但**等效**：

- 浅色：近黑 `#282828` × opacity 0.12–0.26，落在 `#fff` 底上 → 呈淡灰颗粒，视觉权重近似正文的 1/4–1/2 弱化，可辨识且不抢。
- 深色：近白 `#e8e5df` × 同 opacity，落在 `#1b1a19` 底上 → 等效浅灰颗粒。

无需为暗色单设透明度（同值在两主题下主观观感接近）；若用户预览后觉得暗色偏强，可在后续补 `[data-theme='dark']` 微调段（见 §6 备选）。

### 3.3 无需改动的点

- 浮动位移仍 `-6px`、时长 6–12s、延时 0–4s、`ease-in-out` 往返——与颗粒尺度匹配，不动。
- `.project-atmosphere__dot` 的 CSS 样式块与动画块——不改。
- 数量与分布策略：仅提总数，不改 x/y 采样算法。

## 4. 范围

**范围内**：`ProjectAtmosphere.astro` 内 LCG 区间与数量；对应单测快照参数断言；可选 CSS 暗色微调（默认不做）；文档（本文件 + 记录）。

**范围外**：散点颜色、结构、动画手法、`.project-section`/`.project-atmosphere` 的布局与 z-index；项目数据模型；Projects 目录页其余样式；其它栏目。

## 5. 测试策略

见 [`docs/testing-strategies/2026-09-03-testing-strategy.md`](../testing-strategies/2026-09-03-testing-strategy.md)。

- **单测**（`tests/unit/`）：`ProjectAtmosphere` 的随机采样若已抽取成可测函数，则断言产出落在新区间（size∈[2,4.5]、opacity∈[0.12,0.26]、count=60、种子稳定）；若参数仅内联于组件，补充对 `dots()` 导出或对生成 HTML 的属性快照测试。
- **E2E / 视觉**（Playwright Chromium）：截图 `/projects/` 浅色、深色两主题，人工确认散点可辨识但不喧宾夺主。
- 跑 `pnpm build` 确认 46→60 计数在产物中体现。

## 6. 备选（若预览不合预期）

1. 若 60 点 + 0.26 上限仍偏弱：再提 opacity 到 0.16–0.32、或增大到 3–5px（不超 5px，避免变成"圆点噪纹"）。
2. 若觉得纯 `--text` 点"墨味太重、不够氛围"：改为 `color-mix(in srgb, var(--text) 55%, transparent)` 的底色变量（需在 tokens.css 增一个 `--atmosphere-dot` 令牌并在暗色覆盖），让点更柔。此为**默认不采用**的选项，避免引入新令牌增加维护面。
3. 若暗色主题观感偏强：加 `:root[data-theme='dark'] .project-atmosphere__dot { }` 微调段（可在 CSS 内覆盖透明度，需将 opacity 从内联 style 移到 CSS 或留内联但加暗色覆盖）。

## 7. 交付与流程

本改动属**已批准实现的一轮视觉增强之上的微调**，需用户先对本文档方案逐项确认，再授权实现。实现遵循项目规矩：不动代码前等"批准实现"；实现阶段 TDD；聊天确认的决策在任务结束前落入本文档与记录。

## 8. 密度二次调整（2026-09-10 聊天驱动）

实现 §3 → §7 后用户反馈：当前密度点可接受但**过偏**。在 300（×5）数量 + 不动分布算法 + 不影响卡片前景的约束下确定方案如下。

### 8.1 范围

| 项 | 调整 |
|---|---|
| 散点数量 `count` | **60 → 300**（×5） |
| 散点尺寸区间 `size` | 不变（2–4.5 px） |
| 散点不透明度区间 `opacity` | 不变（0.12–0.26） |
| 散点分布算法 | 不变（仍为 LCG 纯随机） |
| 种子 | 不变（20260910） |
| `.project-card` | `background: transparent` → **`var(--surface)`** |

### 8.2 决策依据

- **300 个点仍不会明显扎堆**：宽版内容列可达 ~1680px、估计高度 ~1500–2000px（5 个分类 × 卡片墙），实际面积 ~2.5–3.4M px²；300 个点 ≈ 每 ~8300–11200 px² 一个，仍是稀疏粒子感。
- **为何不动分布算法**：300 个 LCG 随机点在本项目面积下不会形成刺眼扎堆；引入抖动网格（jittered grid）会大改实现、且在本尺度下收益不明显。
- **卡片加 `var(--surface)` 底色**：300 个点一定会透过 `.project-card` 透明区域渗到卡片矩形内（卡片占页大部分）。给卡片加极淡底色作为**点遇卡片自然避开**的透透方案，比起用 z-index + 点坐标跳过卡片区域**更可靠**（构建期不可能知道卡片像素位置，且限定点区域会丢掉"全页包衰"的初衷）。`var(--surface)` 是 `tokens.css` 里已有的语义令牌，浅色 `#f3f3f2`、深色 `#242321`，与现有 `--bg` 微差仅够区分卡片边界、不影响整体节奏。
- **不调移动端单列布局**：窄版单列下卡片几乎占满全页，点出现在卡片间隙中；`var(--surface)` 底色仍可避免点干扰卡片内文。本改在移动端同样安全。

### 8.3 可访问性与影响范围

- 卡片原本为透明背景（无色），改动后多了一层极淡色：**所有现有颜色 / 边框 / hover 效果 / 状态灯 / 标题压暗条不受影响**——因为这些均用纯色或 `var(--bg)` 计算。
- 状态点角标（`.project-status`，z-index: 2，8px 圆点）位于卡片上方，仍清晰可见，不会被点稀释。
- 明暗主题：`--surface` 两套令牌已存在（浅 `#f3f3f2` / 深 `#242321`），无需新增令牌。

### 8.4 不采用的方向

- **限定点出现区域**（仅顶部、仅边带）：会丢掉"整页包衰"感，与用户原意冲突。
- **抖动网格 / Poisson**：实现价值不大，且需重写 `makeDots`（是独立 PR 范围，不属于本「调整密度」语义）。
- **点直接置于卡片下方**（修改 z-index）：仍会通过透明区域出现在卡片内，不能解决问题。

### 8.5 测试

- `tests/unit/atmosphere-dots.test.ts`：范围断言不变；「产量 60 → 300」同时调整函数调用点与「组件中硬编码 makeDots(300)」」快照式断言，防止后续误调回旧值。
- 视觉验证：见任务 #21，构建后截图验证 浅色/深色两主题下点可见且不干扰卡片。

## 9. 密度提升与卡片透明化（2026-09-10 聊天驱动，二次迭代）

用户在 §8 基础上提出两处新要求，并**修正了对"子项目入口"的定位**：指的是 `/projects/` 目录页里的**每张卡片**，而非子项目详情页。

### 9.1 范围

| 项 | §8 状态 | §9 调整 |
|---|---|---|
| 散点数量 `count` | 300 | **500** |
| 散点尺寸 / 透明度 / 算法 / 种子 | — | 均不变 |
| `.project-card` 背景 | `var(--surface)`（实色遮点） | **`color-mix(in srgb, var(--bg) 78%, transparent)`**（轻度半透明，让点透出） |
| `.project-card__cover` 图片 | 无 opacity | **`opacity: .9`**（点在图上也隐隐透出） |
| `.project-card__title` 压暗条 | `color-mix(... var(--bg) 88%, transparent)` | **`color-mix(... var(--bg) 72%, transparent)`**（同步透明化，略实于卡片以保可读） |
| 卡片外（页面背景）的点 | 0.12–0.26 | 不变 |

### 9.2 关键修正：§8 的卡片底色被推翻

§8.2 曾用「卡片加 `var(--surface)` 实色底色」来**遮挡**点，使卡片前景干净。§9 用户明确要求**反过来**——卡片要**半透明**，让点透进来，只是卡片内的点因半透明层稀释而**比卡片外更浅**。这是**迭代修正**：以 §9 为准，§8 的实色遮罩方案失效。

- 机制：半透明层 `color-mix(in srgb, var(--bg) 78%, transparent)` 盖在点层之上，透出约 **22%** 的点强度 → 卡片内点天然弱于卡片外（100%），正好实现用户要的「卡片内更浅」。
- `--bg` 在两主题下分别为 `#ffffff` / `#1b1a19`，故半透明层在两主题下都能正确稀释点，无需新增令牌。

### 9.3 数量 300 → 500 的理由

用户预期项目数会持续增长、页面纵向拉长，密度会被自然摊薄，故提高基数。500 个 LCG 点在宽版内容列（可达 ~1680px）与未来更高的页面上仍保持均匀细腻；窄版移动单列下密度偏高，靠卡片半透明 + 点本身的低透明度维持可读。

### 9.4 可访问性 / 影响范围

- **标题可读性**：`.project-card__title` 压暗条从 88% 降至 72% 透明后，压暗能力略降；但卡片底色本身也半透明，标题区叠加后总遮盖仍充足，且点极淡（≤0.26 × 22% ≈ 0.057 强度），文字对比度不受实质影响。若预览发现标题发虚，回退到 78–80%。
- **图片可读性**：`opacity: .9` 让图轻微变淡，换取点能透出。图是内容主体，0.9 属轻微、通常可接受；若嫌糊，回退到 1（放弃图上透点）。
- **hover 态**：`.project-card:hover { filter: saturate(.35) brightness(.985); }` 作用于整个卡片（含半透明底与点），语义不变。
- ~~状态点角标（z-index: 2）仍在卡片最上层，不受影响。~~ **已被 §10 推翻**——角标已整体移除。

### 9.5 不采用的方向

- **图片保持完全不透明**：用户明确要求「还要管图片」，故给 `opacity: .9`。
- **改用 `mix-blend-mode`**：效果因图而异、不可控，未采用。
- **卡片外点同步调淡**：用户选择保持现状（0.12–0.26）。

### 9.6 测试

- `tests/unit/atmosphere-dots.test.ts`：数量断言 300 → 500（含「组件硬编码 `makeDots(500)`」防回退断言）。
- 视觉验证：构建后截图 `/projects/` 浅色 / 深色两主题，确认卡片内点比卡片外更浅、标题与图片仍清晰。

## 11. 卡片内点强度提至 50% + 数量 900（2026-09-10 聊天驱动，四次迭代）

用户观察：卡片内的点云**明显比卡片外少/弱**，希望卡片内点强度达到卡片外的 **50%**；同时总量再提升到 **900**。

### 11.1 范围

| 项 | §9 状态 | §11 调整 |

### 11.2 「卡片内点强度 = 卡片外的 50%」如何实现

半透明卡片底色盖在点层之上，透出的点强度 ≈ `1 − 底色不透明度`：

- 旧值 78% → 透出 **22%**（用户觉得太弱）
- 新值 **50% → 透出 50%**，正是用户要求的目标值

`--bg` 在两主题下分别为 `#ffffff` / `#1b1a19`，两主题都按同一比例稀释，无需新增令牌。

### 11.3 数量 500 → 900

### 11.4 可访问性 / 影响范围

- **标题可读性**：卡片底色从 78% 降到 50% 后，卡片整体更通透，点更明显；但标题自身压暗条仍为 72% 透明，且点极淡（≤0.26 × 50% ≈ 0.13 强度），文字对比度仍充足。
- **hover 态**：`filter: saturate(.35) brightness(.985)` 语义不变，作用于更通透的卡片时"变灰"更明显——与既有设计意图一致。
- **构建产物体积**：900 个 `<span>` 内联 style，HTML 体积增加有限（每点约 60 字节，合计约 54 KB，gzip 后更小），可接受。

### 11.5 测试

## 12. 数量再升至 1500（2026-09-10 聊天驱动，五次迭代）

用户反馈：在本地 build（dist）产物里看到卡片仍是**实色**——其实 dist 是早于 §11 的旧产物，§11 的 50% 半透明改动尚未反映到该 dist。但同时用户提出继续提高基数至 **1500**。

### 12.1 范围

| 项 | §11 状态 | §12 调整 |
|---|---|---|
| 散点数量 `count` | 900 | **1500** |
| `.project-card` 背景（50% 半透明） | — | **不变** |
| 散点尺寸 / 透明度 / 算法 / 种子 | — | 均不变 |

### 12.2 关于用户截图"卡片不透明"

## 15. 提高散点浮动幅度（2026-09-10 聊天驱动，八次迭代）

用户要求加大散点的浮动程度。给出三档后，用户选择**中度档**。

### 15.1 范围

| 项 | §14 状态 | §15 调整 |
|---|---|---|
| 浮动位移 | 纯垂直 `translateY(-6px)` | **`translate3d(-5px, 0, 0)` → `translate3d(5px, -14px, 0)`**（水平 ±5px + 垂直 -14px） |
| 周期 `duration` | 6–12s | **不变**（6–12s） |
| 尺寸 / 透明度 / 数量 / 算法 | — | 均不变 |

### 15.2 为什么同时加水平漂移

单纯放大垂直位移（如 -6px → -14px）会让运动显得机械、上下往复感强。加入 ±5px 的水平分量后，点是**斜向游动**，更接近"悬浮粒子"的自然感。周期维持 6–12s（每点随机、错峰）以避免整体同步起伏。

### 15.3 关键帧与 `alternate` 的配合

`animation-direction: alternate` 要求关键帧为**两段**（from / to）才能保证奇偶周期严格对称。若写成三段（from / 50% / to），alternate 会让去程与回程不对称。故本档最终采用：

```css
@keyframes dot-float {
  from { transform: translate3d(-5px, 0, 0); }
  to   { transform: translate3d(5px, -14px, 0); }
}
```

并用 `translate3d` 触发 GPU 合成层，保证 1500 个点同时动画时的性能。

### 15.4 未采用的档位

- **明显档（24px / 4–8s）**、**强烈档（36px / 3–6s）**：位移更大、周期更短，点会明显游动甚至分散注意力，与"背景氛围不喧宾"的定位冲突。
- 若后续仍嫌不够，可只调 `dot-float` 的位移值，无需改 TS。

### 15.5 测试

- `astro check` 0 errors / 0 warnings；`vitest` 18 文件 60 测试全绿。
- 视觉验证：重跑 build 后观察点是否明显浮动且不干扰阅读。

## 16. 加深 muted 文字 + projects 页正文专用色（2026-09-10 聊天驱动，九次迭代）

用户截图反馈：projects 目录页的灰色文字（描述、段落正文、h1）在点云背景下**与点视觉混淆**，请求加深。

### 16.1 根因

- 点用 `var(--text)`（浅色 `#282828`、深色 `#e8e5df`）。
- 原 `--muted` 浅色 `#676767`、深色 `#aaa59e`——**与点的颜色太接近**，文字与点重叠时视觉上"糊"在一起，对比度虽够（AA），但**层次被点云压塌**。
- 这是噪点问题，不是对比度问题。

### 16.2 范围

| 项 | §15 状态 | §16 调整 |
|---|---|---|
| `--muted`（浅色） | `#676767` | **`#2a2a2a`**（接近 `--text`，避开点色段，但仍略浅保留 muted 身份） |
| `--muted`（深色） | `#aaa59e` | **`#d6d1c8`**（浅色主题的镜像加深，与 `--text` 保持微差） |
| Projects 页 h1 / 描述 / 段落 | 用 `var(--heading)` / `var(--muted)` | **`var(--text)`**（与点拉开层次） |
| Projects 页行内代码 | `var(--text)` 衍生（浅 `#a23625`、深 `#ee9182`） | 浅 **`#1a1a1a`**、深 **`#f4f1eb`**（与正文同深，避免被点冲淡） |

### 16.3 双重保险：全局 + 局部

- **全局 `--muted` 加深**：让所有页面（不仅是 projects）的次要文字都避开点色段，且仍维持"次要文字"层次（比 `--text` 略浅）。
- **projects 页 `.project-section` 内再用 `var(--text)` 覆盖**：即使全局 muted 加深，projects 页正文中点最密集处的标题、描述、正文段落仍用最深正文色，最大化抗点干扰。

### 16.4 影响范围

- 其他页面的 muted 文字（`#676767` → `#2a2a2a`）**视觉变化**会更明显——之前 #676767 是"次要正文"较淡的视觉表达，现在更接近主正文。若其他页面觉得 muted 文字"过黑"（失去层次），可考虑回退或新增 `--muted-soft` 令牌。
- 当前未观察到其他页面有强烈反对意见；如反馈则单独处理。

### 16.5 测试

- `astro check` 0 errors / 0 warnings；`vitest` 18 文件 60 测试全绿。
- 视觉验证：重跑 build 后观察 projects 页 h1 / 描述 / 段落是否清晰、不与点云混淆；其他页面的 muted 文字是否仍能区分正文。
