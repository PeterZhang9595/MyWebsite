# Project Instructions

Before working in this repository, read and follow
[`docs/development/strategy.md`](docs/development/strategy.md).

Additional mandatory rules:

- Treat `docs/requirements/` as user-owned, read-only source material unless the
  user explicitly authorizes editing a specific requirement file.
- Before changing code, pages, tests, build configuration, dependencies, or
  deployment configuration, obtain explicit implementation authorization as
  defined in the development strategy.
- For any task involving code, pages, builds, tests, or deployment, also read
  and follow
  [`docs/testing-strategies/2026-09-03-testing-strategy.md`](docs/testing-strategies/2026-09-03-testing-strategy.md).
- The Superpowers engineering methodology is permanently adopted with
  constraints. Follow section 16 of
  [`docs/development/strategy.md`](docs/development/strategy.md): project
  documents win on conflict, and no Superpowers step authorizes Git, dependency,
  or deployment changes on its own.
- Do not stage, commit, create or merge branches, push, or revert Git history
  unless the user explicitly requests that Git operation.
- Decisions confirmed in chat must be incorporated into the appropriate project
  documentation before the task ends.
